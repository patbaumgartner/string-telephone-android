# ADR-0001: PBX choice — Asterisk 22 LTS with PJSIP

Date: 2026-10-11
Status: Accepted

## Context

String Telephone needs a self-hosted PBX to provide SIP registration, digest
authentication, call routing between explicitly provisioned accounts, and
RTP audio relay. The companion API (directory, presence, messaging) needs an
authoritative source of SIP registration state.

Candidates considered:

1. **Asterisk 22 LTS with PJSIP** — mature open-source PBX, long-term-support
   release, PJSIP channel driver supports per-endpoint authentication and
   provides AMI actions exposing inbound registration/contact status
   (`PJSIPShowRegistrationInboundContactStatuses`). Large container ecosystem.
2. **Kamailio / OpenSIPS** — SIP routers, excellent at proxying but require
   more manual work for media relay (RTPproxy/RTPEngine) and lack a simple
   built-in voicemail-free dialplan model for small deployments.
3. **FreeSWITCH** — capable but heavier; smaller LTS story for containers;
   config surface larger than needed for one-to-one calling.
4. **No PBX (SIP server embedded in companion API)** — rejecting
   reinvention of REGISTER/INVITE/RTP handling; enormous correctness risk.

## Decision

Use **Asterisk 22 LTS** (22.x, currently 22.11.0) with the PJSIP channel
driver, deployed via Docker Compose. Container image: `andrius/asterisk`
tag `22.11.0_debian-trixie`, pinned by digest
(`sha256:eaa6aaaa09ede2829514769…` for amd64, verified 2026-10-11), which
provides both amd64 and arm64 images. The image is community-maintained but
source-build based on Debian; it is not an official "asterisk" Docker Hub
image (none exists). Image provenance is reviewed at upgrade time.

## Consequences

- PJSIP endpoint configuration is template-driven and versioned in
  `server/asterisk/`; accounts are generated by the provisioning CLI, never
  edited by hand in the shipped tree.
- Presence derivation uses AMI over the Docker internal network only, with a
  least-privilege AMI user; AMI is never published to host or clients.
- Asterisk 22 LTS is expected to receive security fixes through
  approximately 2027; upgrade path documented in `docs/operations.md`.
- SIP digest auth requires per-user secrets (or verifiers) in the PBX
  configuration volume; the volume is operator-protected, and secrets are
  generated by the provisioning tool, never committed.
